# AWS Cloud Engineer Bootcamp

A hands-on portfolio of my AWS learning journey, built one service at a time. Each numbered folder is a project with its own README, screenshots and notes. I'm an IT support professional with 8 years of experience, working toward a junior Cloud / DevOps role.

## How I learn and build

I want to be upfront about how this repository is made:

- **I'm still learning, not an expert.** These projects show my progress and how I think, not production-grade systems.
- **I build the projects myself** in the AWS Console and the command line, following AWS Skill Builder and my own research. I run the steps, troubleshoot the errors and verify the results.
- **I use AI as a tutor.** It explains concepts, reviews my work and helps me understand mistakes.
- **I use AI to improve my documentation.** It helps with structure, wording and clarity. I check the commands and results against what I actually ran.

Each project's README includes a short "what went wrong and what I learned" section, because that's where most of my learning happens.

## What I'm learning along the way

Working through these services has pushed me to learn more than AWS itself:

- **Linux:** I'm learning the command line and system basics, because most cloud servers and containers run on Linux.
- **AWS and the AWS CLI:** I'm building hands-on experience across compute, storage, networking, databases, containers and delivery, using both the AWS Console and the AWS CLI. I'm still learning and building, not an expert.
- **Docker:** As a result of this bootcamp I'm learning Docker and Docker Compose: building images, running containers and publishing images to Amazon ECR.
- **PowerShell:** I'm learning to use PowerShell to run AWS CLI and Docker commands and to test my applications.
- **Networking:** I'm revisiting and strengthening my networking fundamentals, building on my IT support background, and applying them to VPCs, subnets, security groups, load balancers and DNS.
- **System design:** As a result of building these projects, I now plan how the parts of a system connect (flowcharts and diagrams first, then code) before I build.

## How the projects fit together

1. **Foundations (00–06):** the console, identity and access, storage, compute, networking, security and block storage.
2. **Scaling and reliability (07–11):** load balancing, auto scaling, DNS, databases and monitoring.
3. **Automation (12–13):** serverless with Lambda and infrastructure as code with CloudFormation.
4. **Containers and delivery (14–16):** package a Flask app with Docker, store the image in ECR, run it on ECS with Fargate and automate delivery with CI/CD.
5. **Next (17–19):** CloudFront, a capstone, and larger portfolio projects.
